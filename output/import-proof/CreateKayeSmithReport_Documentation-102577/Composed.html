CALLBACK RULE DEFINITIONS

OVERVIEW

 

CALLBACK functions are generally done in conjunction with GENPRINT.  Generally, these functions use data only available at GENPRINT time.  CALLBACK functions are very flexible and can be used in a variety of way.

 

Each CALLBACK function has an accompanying CALLBACK.ini group to designate the BATCHES applicable to that CALLBACK function.  This is required for each CALLBACK function.  Failure to include this in FSISYS.ini will cause the CALLBACK function NOT to execute.

 

To implement a new CALLBACK function, make the following changes.

  1. Add CALLBACK function into CUSCALLB.c.
  2. Add CALLBACK function name into callback symbol table in CUSCALLB.h.
  3. Add clbck_func_def function definitions in CUSLIB.h.
  4. In CALLBACK.ini, add CALLBACK function to < MULTICALLBACKS > group.
  5. In CALLBACK.ini, add < CB_functionname > group, indicating which batches apply to that CALLBACK function.

 

To add an existing CALLBACK function to your peocessing, make the following changes.

  1. In CALLBACK.ini, add or uncomment CALLBACK function to < MULTICALLBACKS > group.
  2. In CALLBACK.ini, add or uncomment < CB_functionname > group, indicating which batches apply to that CALLBACK function.

 

 

 

PROCESSING FLOW

 

Each Callback function receives the following messages, in this order.  They are described below.

 

CALLBACK_INIT

Performed once, at the beginning of the GENPRINT process.  Do any initialization for the function such as VMMList creation, table initialization, loading INI information, etc.

 

FAP_MSGINITPRINT

Initialization performed at the beginning of processing for each formset transaction.

 

FAP_MSGPRINT

Any conditional processing to be performed prior to the actual creation of the print data stream.  This is usually the core of the callback function.

 

FAP_MSGTERMPRINT

Initialization performed at the end of processing for each formset transaction.

 

CALLBACK_TERM

Performed once, at the end of the GENPRINT process.  Do any termination processes for the function such as VMMList destruction, memory free, etc.

SUPPORT FUNCTIONS

 

GetBillDescriptor()

 

As the objects in the FORM object are processed, (ie, individual images), the image name is checked against a list of BILL_DESCRIPTOR Group entries in CALLBACK.INI.  If a match is found, the data associated with the INI entry is placed in the KS data structure in KS.BillDescriptor and processing is returned to the calling function.

 

To add another form to this processing, make sure there is a unique image in the FORM that can be listed in the INI file and therefore, identify the form and provide Descriptor info for Kaye Smith.

 

 

WriteKayeSmithFile()

 

If VMMList is empty, exit.

Read VMMList records, format output line and write to output file.

 

Start a new page when the batch name changes.

WriteKayeSmithBatchWrapUp() – writes out the total mailings line for the batch, initializes some variables and then starts a new page.

 

Allow heading and 50 detail lines per page before starting a new page.

WriteKayeSmithHeader() – First time through, get report title and set run date.
