The order of these steps evolved over time given the initial sequence of distribution.  Over time, it was easier and more stable to alter the effected steps rather than re-engineering parts of the process.

It would be a good time to revamp certain parts of this process, such as grouping the “BATCH 10” related stuff earlier in the process or the elimination of the AGT recipient (except for CN/NR for WY)

This table documents the current DocProd processing.

What is not in this document is the definitions of the supporting reports that EXELA uses to perform its processing.

Also not in this document is the file definition for PBATCH.CSV and DAP.XML.

6

Send the INS copy to the AGENT, instead of mailing to INSURED, according to.

List of Agent #’s, LOB,

Individual pols - ALLTOAGT or RENTOAGT

 

RECIP = INS

There is a list of agent numbers that request ALL of their RB policies to be sent to the AGENT instead of direct mailed to the insured.

There is a list of agent numbers that request ALL of their EN policies to be sent to the AGENT instead of direct mailed to the insured.

 

Step 1: Check by Agent Number

For RB:  If the agent on the policy is in the Agent RB List, then send the policy to the AGENT Batch.

For EN:  If the agent on the policy is in the Agent EN List, then send the policy to the AGENT Batch.

 

PDFs for these policies will be sent to OnBase.

PDFs for these policies will be sent to EXELA – AGENT BATCH.

 

If step 1 resulted in sending the policy to the AGENT BATCH, no need to do Step 2.

Step 2: Check by individual policy

Check PMSP0300.COM0DEST

 

For RB:  If “RENTOAGT” or “ALLTOAGT”, then send the policy to the AGENT Batch.

For EN:  If “ALLTOAGT”, then send the policy to the AGENT Batch.

 

PDFs for these policies will be sent to OnBase.

PDFs for these policies will be sent to EXELA – AGENT BATCH.
