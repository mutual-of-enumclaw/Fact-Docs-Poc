142268:

When an EZ Data Capture (EZDC) form has multiple Sequence Numbers and there are multiple occurrences or iterations of the form, regardless of whether any iteration/occurrence has been deleted, the corresponding BASPEZCAP records in EXTRFILE have incorrect Form Line Numbers (a/k/a iteration number or occurrence number).  For example, suppose an EZDC form has so many fields that it requires two BASPEZCAP records to contain them all.  If the form were added to a unit twice, there would be four records in the BASPEZCAP file.  Two of those records would exist for the first iteration of the form.  They would have Form Line Number 0, but one would have Sequence Number 1 and the other Sequence Number 2.  The other two BASPEZCAP records would exist for the second iteration of the form.  They would have Form Line Number 1, but one would have Sequence Number 1 and the other Sequence Number 2.  In EXTRFILE, there would also be four BASPEZCAP records.  Two would be correct, with one having Form Line Number 0 and Sequence Number 1, and the other having Form Line Number 1 and Sequence Number 1.  However, the other two BASPEZCAP records in EXTRFILE would be incorrect.  Although they would each have the correct Sequence Number, 2, one would have Form Line Number 2, which should be 0, and the other would have Form Line Number 3, which should be 1.

 

The Form Line Number resequencing logic in program FORMCBLPGM, implemented under FSIT 116316, cannot work properly when a form has more than one Sequence Number and iteration, because the wrong input file is being used to build the TEMPEZCP file in program BASEZEXTRC.  TEMPEZCP is used by FORMCBLPGM to build the BASPEZCAP records for EXTRFILE.  Program BASEZEXTRC should use the BASLEZCAP2 logical file, which is sorted by Form Line Number then Sequence Number, as input.  However, it is using the BASPEZCAP physical file, which is sorted by Sequence Number then Form Line Number.
