OVERVIEW – CSC Base Functionality

Revised program FORMCBLPGM's processing of ASBECPP ALR form records.

At the top of program FORMCBLPGM, the BASSYS1700 file is read for 'PRNT ALR STATIC FORM ONCE/MOD' entry.

  • If the entry is present and set to 'Y', the 'PRNT ALR STATIC FORM ONCE/MOD’ functionality is turned on.

From this point forward, assume the 'PRNT ALR STATIC FORM ONCE/MOD’ function is turned on.

In FORMCBLPGM ASBECPP processing before the record is written to the EXTRFILE

  • When the ASBE record has a "new" Form Action Code, meaning it should print, new program BASP029I01 is called to determine if the form is variable or static.
  • BASP029I01 reads TBPP029 for the form.
  • If the form/edition date is in TBPP029, then it is variable; otherwise, it is static.
  • But not all forms with variable fields need to be included in TBPP029.  A form with variable fields can be treated as if it were a static form, and therefore, only printed once for the policy term.

Going forward in this discussion…

Variable means the form is included in TBPP029.

Static means that the form is NOT included in TBPP029.

Back in FORMCBLPGM, if the form is static, BASDAP2500 file is read using the policy key and form.  If a BASDAP2500 match is found, then the form has already printed once for this module and should not print again now, so its Form Action Code is changed to the "old" value that corresponds to its current "new" one.

If no BASDAP2500 match is found, then the form has not printed for this module and can print now.  Since its Form Action Code is already "new", it is not changed.  However, a record is written to BASDAP2500 for the policy key and form, to prevent the form from printing later for future endorsement transactions under this module.

DISPOSITION OF BASDAP2500 RECORDS

If FORMCBLPGM is being executed during the batch cycle, the new BASDAP2500 record's status will be 'V'erified.  However, if FORMCBLPGM is being executed via Immediate Print ("Generate Policy Dec"), the new BASDAP2500 record's status will be 'P'ending.

During Immediate Print, after the user has viewed the policy documents online, if he/she clicks the "Archive" button to save the documents, then program BASIMPRU01 will change the policy's BASDAP2500 records from ‘P’ending to ‘V’erified.

If the user chooses not to archive the documents and clicks the “BATCH” button so that the documents are generated in a future batch cycle, the pending BASDAP2500 records will be left hanging.

Thus, in FORMCBLPGM, at the top of the ASBECPP processing, we will delete any ‘P’ending BASDAP2500 records for the policy by calling new program BAS2500D01.

REPRINT at Endorsement

This new functionality will not affect existing logic for form reprint during endorsement.

If a form has been marked for reprint, it will still print regardless of whether

  1. it's static or variable
  2. and has or has not printed previously during the same module.

RENEWALS

The new functionality, when turned on, will affect renewal form print control as follows:

  1. When renewal form print control is turned on and there are renewal and endorsement transactions in the same cycle for the same policy and documents have not been generated yet for the renewal transaction
  • Instead of all forms being marked "new" to print, all variable (refer to above definition of variable) forms will be marked "new", but only the first occurrence of each static (refer to above definition of static) form will be marked "new."
  • Subsequent occurrences of each static form will be marked "old" so they won't print.

 

  1. When renewal form print control is turned on and a renewal is processed without an endorsement transaction in the same cycle for the same policy
  • Since rating has determined which forms should print at renewal, the Form Action Code set by rating on variable forms will not be changed.
  • Also, any "old" Form Action Codes set by rating on static forms will not be changed.
  • However, any static forms marked "new" by rating will be re-evaluated in FORMCBLPGM, so only the first occurrence of a form will stay "new."
  • Subsequent occurrences of that form will be marked "old" so they will not print.

Program BASCKFORRB, which was implemented for renewal form print control, was modified here to use the WRKP0000 file during batch processing and the PMSP0000 file during Immediate Print processing.

The new standardized message retrieval and error handling routines were added to each program modified or created by this FSIT.

PLEASE NOTE: FORMCBLPGM will change the Form Action Code only on the ASBECPP record that's being written to the print extract file.  It will not change the Form Action Code on the form record in the actual ASBECPP file.

 

Mutual of Enumclaw Information

These forms should be included in TBPP029 (This information may change as testing occurs)

  • All forms that are associated with interest and are used in MOE12AT processing (looking for form action code set via Re-Print option).  The CSC base function provides that the reprint functionality is unchanged.  Need to verify this with regard to these types of forms.  3A – CA2001, 3C – EA4605, for example.
  • All EZDATA forms
  • Forms that contain variable information that needs to be printed at EN, assuming that the endorsement processing creates an ASBE record with ‘new’ form action code.
  • Not sure about WIP forms yet…

 

OTHER NOTES

If a form is included in TBPP029, it will print for EN’s if it meets DocProd triggers.

If a form is NOT included in TBPP029, it will NOT print for EN’s regardless if it meets DocProd triggers.

Variable fields on a form do not automatically mean that it should or will be printed at EN…only if it is included in TBPP029.
