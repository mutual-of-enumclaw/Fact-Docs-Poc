This transaction list is then used by the GenDataprogram as it processes transactions.GenTrn uses settings in the FSISYS.INI and TRNDFDFL.DFD files todetermine how to process the transactions. These files provide theGenTrn program with information about the format and structure ofthe extract file, such as how to determine where each new recordstarts.ERRORFILESGenTrn produces an error file to note any transactions it could notprocess correctly. This file allows you to find and correct processingerrors. The information is recorded by transaction. This file can beviewed using a text editor.LOGFILESWhen GenTrn is run, the program creates log files that record eachtransaction processed. This file can be viewed using a text editor.Note:A log file and error file is created with each GenTrn process.Previous files are overwritten each time. It is important that a backupbe made before running GenTrn.GenData ProcessThe GenData program takes the TRNFILE, created by the GenTrnprogram, and applies processing rules to those transactions anddata. The GenData program creates batch files, NAFILE.DAT andPOLFILE.DAT, for the GenPrint program. It also creates a manualbatch file, MANUAL.BCH, for the GenWIP program and ERRORBATCHthat contains all transactions that had errors posted. AU T O M A T E D C YC L E SExceed and POINT IN Document ProcessingGenData Output FilesNAFILE.DATGenData creates a NAFILE.DAT file, commonly referred to as the NAfile, to store image and variable field information. The GenPrint pro-gram uses this file along with the POLFILE.DAT file, produced byGenData, to print the forms.If the data is incomplete and GenData cannot complete the form, itcreates a manual batch file. The GenWIP program then creates sepa-rate DAT and POL files for each incomplete transaction. These filesprovide the entry system with the information it needs to open theform so a data entry operator can add the missing data. This is asemicolon-delimited text file.POLFILE.DATPOLFILE.DAT, commonly referred to as the POL file, defines the formset used for a specific transaction. GenData creates this file, whichis used by GenPrint, GenWIP, and GenArc. For instance, if the data iscomplete, GenData creates an NA file and a POL file. These files areused by GenPrint, along with the batch files, to produce the print-ready file.If the data is incomplete and GenData cannot prepare the form forprinting, it creates a manual batch file. The GenWIP program thencreates separate files to house the NA file and POL file data for eachtransaction. These files provide the entry system with informationneeded to open the form, allowing missing data to be added by dataentry operators.NEWTRN.DATGenData creates the NEWTRN.DAT file, which contains alltransactions that processed without error. This file tells GenArcwhere to find data in the NAFILE.DAT file and which forms to use inthe POLFILE.DAT file.BATCHFILESGenData creates files with the extension BCH, called batch files. Itlists the transactions to be included in each batch as specified inthe FSISYS.INI file settings. Batch files are used as trigger files byGenPrint and GenWIP. Batch files indicate which transactions shouldbe printed in a given batch job. GenPrint uses batch files to printcompleted forms. The GenData program also creates manual batchfiles, which record incomplete transactions. These manual batchfiles are used by GenWIP. Transactions that had errors are placed inthe ERROR.BCH file.MANUAL.BCHGenData creates the MANUAL.BCH file if it is unable to complete theprocessing of a form set. AU T O M A T E D C YC L E SExceed and POINT IN Document ProcessingGenWIP ProcessGenWIP receives information about incomplete transactions fromthe GenData program. This information is stored in manual batch(MANUAL.BCH) files.Data can be corrected and missing information supplied to completethe form in Documaker Workstation. Once completed, the form canbe resubmitted for processing by the GenData program.GenWIP Incomplete TransactionsGenWIP creates the following files as it prepares incomplete transac-tions for further processing with the entry system:WIP.DBFWIP.DBF contains information about the incomplete transactionsextracted by GenWIP from the NAFILE.DAT file and the POLFILE.DATfile created by GenData. The WIP.MDX file serves as an index to thisfile.WIP.MDXThis is an index to the WIP.DBF file.00000001.DATUses the MANUAL.BCH file produced by GenData. GenWIP creates aseparate data file for each incomplete transaction from theNAFILE.DAT file. These files are numbered and have an extension of.DAT. They are like NAFILE.DAT except there is only one transactionper file.00000001.POLUses the MANUAL.BCH file produced by GenData. The GenWIP pro-gram creates a separate POL file for each incomplete transactionfrom the POLFILE.DAT file. These files are numbered to correspondwith their matching data file and contain information about theform set on which the system should place the data. They are likePOLFILE.DAT except there is only one transaction per file.Note:The naming convention of the DAT and POL files are controlledby the WIP.DFD files.UNIQUE.DBFThe UNIQUE.DBF file contains the last number for the WIP file thatwas created. When a WIP file is created, a unique number is gener-ated so that no WIP file is overwritten. This file, therefore, shouldnot be modified, renamed or deleted. The highest number that willbe generated for WIP files is FFFFFFFF, which is 4,294,967,295. Afterthis number, the counter resets to 00000001.©Copyright 2008 CSC. D O C U M E N T P R I N T E R RO R H A N D L I N GControlling the Deletion of the Temporary Directories Created by Document Print (.NET Version)Controlling the Deletion of the TemporaryDirectories Created by Document Print (.NETVersion)......................................................Whenever the first call is made to Document Print for a transaction,Document Print will create a temporary directory so the batch pro-grams (GEN executables) can process. After the transaction has beensent to Archive or WIP, the temporary directory is automaticallydeleted. If an error occurred in the process, the temporary directoryis not deleted for research purposes. However there may be a needto not delete the temporary directory when no errors occurred. Thereason can be for researching a problem with a document contain-ing incorrect data.No matter what the reason is for the deletion of the temporarydirectory, it can be controlled by a setting in the DOCPRINT.INI file.To turn on or off this process, follow the steps below:1Open DOCPRINT.INI, located in <drive>:\<target>\DocPrintSer-vice\AppServer\Bin.2Under the appropriate environment section, set the followingoption:DELETE_TEMP = Y or NWhere:Y = Delete temporary directory on successful completion(default)N = Do not delete temporary directory on successful comple-tion3You will need to restart IIS for the change to take.Note:You can use the DPCLEANUTIL utility job to delete temporarydirectories based on a time elapsed from creation date. Refer to theDocument Print Technical User Guide for more information.©Copyright 2008 CSC. All Rights Reserved.Production Guide for Print - Common19
