Versioning Forms

 

OPTION 1: The form is versioned due to an edition date change.

 

Scenario/Sample:

Current Form: BP0003 0110

New Form:  BP0003 0713

 

 

Step 1: Document the update in the Sharepoint – “DocProd Master Forms Spreadsheet V00.xlsx”

 

 

Step 2: Identify and define the new FAP File name.  In this example the form was versioned from “A” to “B”.  Using the DocProd Image Editor and other conversion tools, create the new FAP file in the FORMS folder.  In this example, the new file name in BP0003B.FAP.  This process also creates the corresponding BP0003B.DDT file in the DDTLIB folder.

 

BP0003A

BP0003B

 

 

 

Step 3: In the DEFLIB\FORMS.DAT file, create a new entry for the new version of the form.

 

;MOE;BOP;BP0003    0110;;R;;BP0003A|FD3<INS(0)>;

;MOE;BOP;BP0003    0713;;R;;BP0003B|FD3<INS(0)>;

 

 

NOTE:

For some forms (CA/FA or GL/FGL), the same form could be applicable to CPP and FRM.  Be sure to version both and test both.

 

Step 4: In the DEFLIB\SETRCPTB.DAT file, create a new entry(s) for the new version of the form.

 

;MOE;BOP;BP0003    0110;;NB,RB,EN;INS

;;0;0;0;1;TBLOFF,ASBECPL1,BEB8NB,BP0003,BEAMDT,11001,BEDUST,(2,4,6,8,0,A,C,E,G)|TBLOFF,PMSP0200,ISSUE0CODE,~Q;

 

;MOE;BOP;BP0003    0713;;NB,RB,EN;INS

;;0;0;0;1;TBLOFF,ASBECPL1,BEB8NB,BP0003,BEAMDT,11307,BEDUST,(2,4,6,8,0,A,C,E,G)|TBLOFF,PMSP0200,ISSUE0CODE,~Q;

 

 

SETRCPTB.DAT Definitions

 

;MOE;BOP;BP0003    0713;;NB,RB,EN;INS

Key 1 – Master Company

Key 2 – Line of Business

External Form Name (Matches what is in FORM.DAT)

Internal Image Name

Transaction Codes applicable

Recipients

 

;;0;0;0;1;TBLOFF,ASBECPL1,BEB8NB,BP0003,BEAMDT,11307,BEDUST,(2,4,6,8,0,A,C,E,G)|TBLOFF,PMSP0200,ISSUE0CODE,~Q;

Count Search Parameter

Trigger Code (0, 1 or 2)

Number of objects on the image

Number of objects on a different first image

Trigger Code (default is 1, some custom rules have different codes)

T/F Search Parameter

Optional (not shown) – Custom Recipient Rule

Optional (not shown) – Custom Recipient Rule Data Parms

 

 

In this example, one BP0003 0713 form is triggered if....

  1. All parts of the T/F search parm evaluated to TRUE....ie...
    1. There is an ASBECPL1 record in the EXTRFILE.DAT where
      1. Form Name (BEB8NB) = “BP0003”
      2. Form Edition Date = “11307”
      3. Form Action Code (BEDUST) is Active (2,4,6,8,0,A,C,E,G)
    2. Note that the “|” character separated the 2 distinct part of the T/F parameters
    3. The transaction is NOT a QUOTE
      1. PMSP0200 where ISSUE0CODE not = to “Q”

Not shown

  1. If the Count parameter is used, then the search parm must return a count greater than 0

 

Not shown

  1. If custom rules are used, the Count parm (if used) and the T/F parm (if used) must evaluate to TRUE before the custom rule is executed.

 

 

 

 

NOTES:

 

ALR makes the decision as to which form to attach to the policy.  DocProd simply triggers and prints what ALR provides.

 

Never delete anything out of

DEFLIB\FORM.DAT

DEFLIB\SETRCPTB.DAT

 

Always keep the DDTLIB\ *.DDT file

Always keep the FORMS\ *.FAP file

 

Update the Master Forms spreadsheet on the server

"\\homer\it\point\point\DocProd Forms\DocProd Master Forms Spreadsheet V00.xlsx"
